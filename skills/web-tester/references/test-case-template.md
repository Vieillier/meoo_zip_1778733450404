# 测试用例模板规范

## 测试用例结构

每个测试用例应包含以下核心要素：

### 基本信息
- **用例编号**：唯一标识符，格式 `TC-[模块]-[序号]`（如 TC-LOGIN-001）
- **用例名称**：简洁描述测试目标
- **测试类型**：UI测试 / 功能测试
- **优先级**：P0（高）/ P1（中）/ P2（低）
- **前置条件**：执行测试前必须满足的条件

### 测试步骤
每个步骤包含：
1. **步骤描述**：具体操作动作
2. **测试数据**：输入数据（如有）
3. **预期结果**：该步骤应达到的效果

### 测试数据
- 有效数据示例
- 边界值数据
- 异常数据

### 预期结果
- 最终预期状态
- 关键验证点

## 测试用例示例

```markdown
## TC-LOGIN-001：用户正常登录

**测试类型**：功能测试
**优先级**：P0
**前置条件**：用户已注册且账号状态正常

### 测试步骤
| 步骤 | 操作 | 测试数据 | 预期结果 |
|------|------|----------|----------|
| 1 | 打开登录页面 | - | 页面正常加载，显示登录表单 |
| 2 | 输入用户名 | test@example.com | 输入框显示输入内容 |
| 3 | 输入密码 | Password123 | 密码以掩码形式显示 |
| 4 | 点击登录按钮 | - | 跳转至首页，显示用户信息 |

### 测试数据
- 用户名：test@example.com
- 密码：Password123

### 预期结果
- 登录成功，跳转至首页
- 页面显示用户欢迎信息
- 用户状态变为已登录
```

## UI测试用例要点

### 布局验证
- 元素位置是否符合设计稿
- 响应式布局在不同视口下的表现
- 元素间距和对齐方式

### 样式验证
- 字体、颜色、大小是否符合规范
- 主题切换是否正常
- 动画效果是否流畅

### 交互验证
- 悬停、点击、聚焦状态
- 表单输入反馈
- 错误提示显示

## 功能测试用例要点

### 正常流程
- 核心业务流程的完整执行
- 数据正确性验证
- 状态转换验证

### 异常流程
- 错误输入处理
- 网络异常处理
- 权限控制验证

### 边界条件
- 输入边界值
- 并发操作
- 数据量极限
